# 虎扑懂哥履历：功能构想与当前实现

2026-11-19 改版：从观点变化检查调整为轻松、有细节的话题小传。下面这一节描述当前方向，后面的早期构想仅供历史参考。

## 当前产品方向

输入一个用户和一个话题，看看他对具体事物的评价、各时期关注点，以及值得读的原声。不以寻找矛盾或改口为任务。

- **一句话懂他**：与这批发言贴切的短标题和整体观察，避免千人一面的套话。
- **鲜明看点**：最多四个关注点，解释他夸什么、嫌什么、表达有什么特点，每项能回看原声。
- **原声精选**：最多六条代表评论及简短点评，兼顾有内容的发言与真实高点亮评论。
- **那阵子在聊什么**：按发言时间分期，讲当时的评价和代表原声；可以一直持同样看法，不强迫编出转变。
- **原文抽屉**：展示原文、独立标注的引用上文、采集时间和原帖链接。

实现要点：
- AI 提示词以社区编辑口吻写作，用具体细节和贴切比喻增加趣味，不编金句、不猜私人身份和动机。
- 点亮数来自数据库：回帖 light_count、发帖 lights；未知值不伪造为有亮度的热评。
- 样本上限60条，大数据量时最多20条高点亮记录与时间覆盖样本混合，去重后保留点亮最高的真实记录。
- 引文仍由程序从原始正文片段回填；主题与精选引用只能指向已验证观点。
- 新格式 report_version=2，保留原查询缓存键；旧格式可查看，但提示重新生成，不显示旧版对照模块。
- 前后对照不再是新版生成任务。追问、分享图、预测簿留待后续。

## 以下为早期构想（历史参考，已被上述方向调整）

## 一句话定义

输入一个用户和一个话题，把已收录的相关发言整理成可追溯的观点时间线：他什么时候说过什么、哪些判断保持一致、哪些发生变化，以及证据能支持到什么程度。

产品名保留虎扑语感；分析结果使用中性描述，不默认把变化称为打脸，也不把网络发言推断为真实身份或私人经历。

## 要回答的问题

1. 这个用户对某个对象究竟持什么观点？
2. 这些观点什么时候出现，后来如何变化？
3. 两句看似矛盾的话，是否讨论同一对象、维度和条件？
4. 有哪些明确的预测，原话如何，是否具备复盘条件？
5. 哪些结论证据不足，还需要更多记录？

## 用户流程

1. 在现有用户分析页进入“懂哥履历”，沿用当前用户。
2. 输入话题，如“小米汽车”“某位球员”，选择全部已收录时间或指定范围。
3. 展示相关记录数量、时间覆盖及数据更新时间；缺少记录时提示抓取或调整话题。
4. 生成履历，先看一句话总结，再浏览阶段时间线。
5. 点击观点查看原话、上下文、日期、帖子标题及原帖链接。
6. 选择两个阶段进行对照，或基于同一批证据追问。

首版以手动输入话题为主；自动推荐常聊话题可后续补充。

## 页面构成

### 1. 数据范围条

- 用户、话题、查询时间范围、实际记录起止时间。
- 检索命中数、用于分析的记录数、独立帖子数、最近抓取时间。
- 明确标注“基于已收录公开发言”，展示无记录区间与截断情况。
- 同一个帖子内连续回复不应被视为多个独立事件；重复发言也不应放大证据强度。

### 2. 总览卡

- 一句话概括主要变化，附证据入口。
- 按维度概括最近有记录的观点，例如价格、外观、质量，而非单一“粉/黑”标签。
- 分别呈现保持一致的判断、发生变化的判断、暂时无法判断的部分。
- 避免无校准依据的“87% 可信度”之类数字；使用“多条独立记录支持 / 单条记录 / 语境不足”，并说明原因。

### 3. 观点时间线

按实际发言形成阶段，不强制每月一个节点，也不要求必须有转变。

每个节点包含：
- 时间或时间范围。
- 阶段标题，例如“认可外观，价格态度尚不明确”。
- 对象、讨论维度、立场、适用条件。
- 简短归纳及一至三条代表原话。
- 支持记录数、独立帖子数、反例或混合意见。
- 证据不足、玩梗或反讽可能性提示。

### 4. 前后观点对照

左右排列两个阶段的原话、时间、对象和条件；在中间说明关系：

| 类型 | 判定说明 |
|---|---|
| 一致 | 同一维度判断基本一致 |
| 补充 | 新增信息，不推翻原有判断 |
| 条件变化 | 价格、版本、赛季、伤病等前提已改变 |
| 观点变化 | 对象和条件足够可比，表达的判断不同 |
| 无法判断 | 对象不清、上下文不足、疑似反讽或只有引用 |

只对有可比证据的记录做对照。系统找到的最早不同发言，只能称为“已收录记录中的变化节点”，不能当作真实转变时刻。变化原因只有用户原话明确说明时才归因，否则标注未知。

### 5. 证据抽屉

- 原始发言、发言时间、帖子标题、引用的上文、原帖入口。
- 高亮支持当前结论的原文片段，同时保留完整已存文本。
- 区分作者自己的话和被引用用户的话。
- 原帖打不开时仍可查看已采集文本及采集时间，不声称现时内容仍然相同。

## 示例（完全虚构，仅说明交互）

话题：某款汽车的购买建议。

| 时间 | 原话 | 履历解释 |
|---|---|---|
| 3 月 | “这个价我不推荐，便宜两万可以考虑。” | 对价格有条件地否定，不能概括成全盘反对 |
| 6 月 | “外观确实不错，不过现在价格还是高。” | 新增外观评价，价格判断保持一致 |
| 9 月 | “现在降两万了，这个价可以买。” | 条件兑现，属于购买建议变化，不能称为自相矛盾 |

总览可写：“在已有记录中，他始终认可降价后的性价比；购买建议随价格条件变化，未发现足以证明前后矛盾的记录。”

## 首版范围

包含：
- 单用户、单话题、指定时间范围。
- 基于本地已收录发帖与回帖，检索后生成履历。
- 按维度归纳、阶段时间线、可比观点对照和证据展开。
- 结果缓存、数据更新后显示过期状态、手动重新生成。
- 样本不足、无相关记录、全程观点一致的正常展示。

后续再做：
- 自然语言追问，复用现有问答。
- 分享卡片及多话题个人履历。
- 增量合并新观点和多个用户对比。
- 预测记录簿：提取明确预测，保留条件、期限和原话；有独立结果证据才判定命中，否则待验证。

首版不做真实人物的“打脸排行榜”、自动判定预测胜率、跨平台身份关联，也不自动发布内容。

## 与现有项目的衔接

- 数据来源：用户发帖、回帖及引用上下文。
- 检索入口：复用问答相关检索能力，并补足话题别名与时间过滤。
- 降噪：复用相似度分析思路，重复内容聚为一组，保留日期与频次。
- 页面：作为用户分析中的新视图；成分卡可链接到相关话题履历。
- 生成功能：先筛选证据，再抽取观点，最后合并阶段；不直接把所有文本交给模型自由撰写人物故事。

建议的处理流程：
1. 解析话题、对象及别名，检索相关记录。
2. 清理引用归属、去重；按时间分段取样，避免只看到最近或最热门发言。
3. 抽取结构化观点：对象、维度、立场、条件、原文片段和来源 ID。
4. 比较可比观点，形成阶段；保留反例，不为叙事顺畅删除相反证据。
5. 生成总结并校验所有证据 ID 归属当前用户，原话可在原始记录中找到。
6. 缓存结果，记录数据版本、生成版本及覆盖范围。

最小结果结构可分为：
- report：用户、话题、范围、数据版本、生成时间、覆盖说明。
- claims：结构化观点、证据 ID、原文片段及不确定性说明。
- phases：阶段范围、摘要、观点引用。
- comparisons：前后观点引用、关系类型及理由。

这是实现方向，具体表和接口待开发时结合现有结构确认。

## 首版验收重点

- 所有展示为原话的文字都能对应到真实的已存记录；示例不能进入真实报告。
- 一条记录也能正常展示，但不能包装成长时间的稳定立场。
- 数据稀疏或未抓取期间不被解释为沉默、退坑或改变立场。
- 同一品牌不同车型、同一球员不同赛季不直接混为同一判断。
- 引用别人的话不被计入当前用户立场。
- 降价等条件变化不会被简单标为矛盾。
- 有反例、混合意见或疑似反讽时，报告保留不确定性。
- 每个关键总结能点回证据；只有不确定证据时允许输出“无法判断”。

产品验证重点：用户是否愿意展开证据、是否能找到值得阅读的观点变化、是否认为总结准确。先用少量人工核对的案例验证，再考虑扩大话题和生成规模。
