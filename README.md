# hupu-bot

虎扑论坛命令行工具 + Web 分析平台，支持回复帖子、获取消息、抓取回帖/发帖数据、相似度分析、AI 智能分析。

## 功能

- **回复帖子**: 向指定帖子发送回复，支持引用回复
- **点赞回复**: 点赞/取消点赞某条回复
- **搜索帖子**: 搜索虎扑帖子，支持板块过滤和排序
- **获取消息**: 查看"提到我的"、"评论"、"亮了/推荐"等消息通知
- **板块帖子**: 获取指定板块的帖子列表
- **帖子详情**: 获取帖子正文内容和热门回复（按点赞排序）
- **获取回帖**: 抓取用户的所有回帖记录并存入数据库
- **获取发帖**: 抓取用户的发帖记录并存入数据库
- **相似度分析**: 分析用户回帖中的重复/近似内容，识别复读模式
- **AI 智能分析**: 基于 AI 对用户的回帖/发帖进行深度画像分析
- **查成分**: 基于用户回帖/发帖生成结构化"成分卡"（粉籍、抽象指数、口头禅、经典语录、历史黑点）
- **魂穿模式**: AI 学习目标用户的说话风格，模仿其口吻生成回复（嘴替）或与之对线（克隆人聊天）
- **Web 可视化**: 启动 Web 服务，通过图表、词云、AI 分析报告等形式展示数据

## 安装

```bash
cd hupu-bot
cargo build --release
```

## 配置

复制配置文件并填入你的凭据：

```bash
cp config.example.json config.json
```

```json
{
  "cookie": "smidV2=...; u=...; csrfToken=...; ...",
  "provider": "deepseek",
  "api_key": "sk-..."
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `cookie` | 是 | 虎扑登录 Cookie，从浏览器 DevTools 复制，需包含 `smidV2` 字段 |
| `provider` | 否 | AI 提供商：`deepseek` / `ollama` / `openrouter` / `opencode`（默认 deepseek） |
| `api_key` | 否 | AI API Key，用于 AI 智能分析功能 |
| `model` | 否 | 模型名，为空自动使用对应 provider 的默认模型 |
| `max_concurrency` | 否 | AI 请求最大并发数（默认 3） |

> `puid` 和 `shumei_id` 会自动从 cookie 中的 `u` 和 `smidV2` 字段解析，无需手动配置。

### 获取 Cookie

**推荐方式 — 自动提取：**

```bash
cargo run -- extract-cookies
```

程序会自动查找系统中的 Chrome 或 Edge 浏览器，启动调试窗口打开虎扑论坛，你只需登录虎扑账号，Cookie 会自动保存到 `config.json`。

> **Windows**: 自动从注册表获取浏览器安装路径，并提示关闭后台运行的浏览器进程以确保调试端口可用。
> **macOS**: 从标准 Applications 路径查找浏览器，同样支持关闭后台进程。
> **手动方式**（自动提取失败时）：

1. 打开 Chrome 浏览器，登录虎扑
2. 按 F12 打开开发者工具
3. 切换到 Network 标签
4. 刷新消息页面 `https://my.hupu.com/message?tabKey=1`
5. 找到任一请求，查看 Headers
6. 复制 Cookie 整行（从 `smidV2=...` 开始到结尾）

## 使用

### 自动提取 Cookie

自动从 Chrome/Edge 浏览器提取虎扑登录 Cookie，无需手动复制。

```bash
cargo run -- extract-cookies
```

**工作流程**:
1. 检测是否已有带调试端口的浏览器在运行，有则直接提取
2. 在系统中查找 Chrome 或 Edge 浏览器的安装路径
3. 检测并提示关闭浏览器后台进程（需用户确认）
4. 启动浏览器调试窗口，自动打开虎扑论坛
5. 等待登录完成（检测到 `smidV2` 字段即为登录成功）
6. 自动提取 Cookie 并保存到 `config.json`

**注意事项**:
- 如果浏览器已经在运行，后台进程会阻止调试端口开启，程序会提示你确认关闭进程
- 登录超时时间为 5 分钟，超时后需要重新运行
- Cookie 中的 `puid` 和 `shumei_id` 会自动解析
- 已有的 `provider` / `api_key` 等配置会被保留

### 点赞回复

```bash
# 点赞某条回复
cargo run -- like -p 638074156 -c 201801 -f 278

# 取消点赞
cargo run -- like -p 638074156 -c 201801 -f 278 --undo
```

**参数说明**:
- `-p, --tid`: 帖子 ID
- `-c, --pid`: 回复 ID（要点赞的那条回复的 pid）
- `-f, --fid`: 板块 ID（如 278 汽车区）
- `-u, --undo`: 取消点赞

### 搜索帖子

```bash
# 基本搜索（默认综合排序）
cargo run -- search -k "特斯拉"

# 指定页码和条数
cargo run -- search -k "小米汽车" -p 2 -l 10

# 指定板块过滤
cargo run -- search -k "比亚迪" --forum 278

# 按排序方式
cargo run -- search -k "问界" -s light

# JSON 格式输出
cargo run -- search -k "华为" -f json
```

**参数说明**:
- `-k, --keyword`: 搜索关键词（必填）
- `-p, --page`: 页码（默认 1）
- `-l, --limit`: 限制条数（默认 20）
- `-f, --format`: 输出格式（table / json / simple）
- `--forum`: 板块 ID 过滤
- `-s, --sort`: 排序方式（默认 `general`）
  - `general`: 综合
  - `createtime`: 最新
  - `createtimeasc`: 最早
  - `replytime`: 回复时间
  - `light`: 亮回复数
  - `reply`: 回复数

### 回复帖子

```bash
# 普通回复
cargo run -- reply -t 1 -p 638852430 -c "这是我的回复内容"

# 回复指定发言（引用回复）
cargo run -- reply -t 1 -p 638852430 -c "回复你的发言" -q 201801
```

**参数说明**:
- `-t, --topic-id`: 板块 ID（如 1）
- `-p, --tid`: 帖子 ID（URL 中的数字）
- `-c, --content`: 回复内容
- `-q, --quote-id`: 引用回复ID（可选），对应被引用发言的 `pid`

**字段映射说明**:

| 字段名 | 所在位置 | 含义 | 用法 |
|--------|---------|------|------|
| `pid` | mentions API 返回 | 发言/回复的唯一标识 | 从消息列表中获取，用于定位要回复的具体发言 |
| `quoteId` | createReply API 请求 | 被引用发言的 ID | 发送回复时，填入对方的 `pid`，实现引用回复 |

流程示例：
1. 通过 `cargo run -- mentions --format json` 获取消息列表
2. 从 JSON 中找到目标消息的 `pid` 字段（如 `"pid": xxxxxx`）
3. 使用 `-q xxxxx` 参数回复该指定发言

```bash
# 1. 先获取消息，记录 pid
$ cargo run -- mentions --format json
[
  {
    "username": "某用户",
    "content": "原始发言内容",
    "tid": 638852430,
    "pid": xxxxx    # ← 记录这个 pid
  }
]

# 2. 使用 pid 作为 quote-id 回复
$ cargo run -- reply -t 1 -p 638852430 -c "回复内容" -q xxxxx
```

### 获取消息

```bash
# 获取"提到我的"消息（默认20条）
cargo run -- mentions

# 获取"评论"消息
cargo run -- mentions --tab comments

# 获取"亮了/推荐"消息
cargo run -- mentions --tab likes

# 过滤24小时内的消息
cargo run -- mentions --since 24h

# 过滤7天内的消息
cargo run -- mentions --since 7d

# 最多获取50条消息
cargo run -- mentions --limit 50

# 最多翻3页获取消息
cargo run -- mentions --pages 3

# JSON 格式输出
cargo run -- mentions --format json

# 组合使用
cargo run -- mentions --tab comments --since 48h --limit 10 --format simple
```

**参数说明**:
- `-t, --tab`: 消息类型
  - `mentions`: 提到我的（默认）
  - `comments`: 评论
  - `likes`: 亮了/推荐
- `-s, --since`: 时间过滤
  - `24h`: 24小时内
  - `48h`: 48小时内
  - `7d`: 7天内
  - `2026-03-20`: 指定日期之后
- `-l, --limit`: 限制条数（默认 20）
- `-p, --pages`: 最大翻页数（默认 5）
- `-f, --format`: 输出格式
  - `table`: 表格格式（默认）
  - `json`: JSON 格式
  - `simple`: 简洁列表格式

### 获取回帖

抓取用户的所有回帖记录并存入 SQLite 数据库，供后续分析使用。

```bash
# 获取用户回帖（默认10页，每页10条）
cargo run -- replies -e 27066519444214

# 获取更多页
cargo run -- replies -e 27066519444214 -p 20 -s 20

# 增量爬取：只爬取尚未入库的新回帖，遇到整页已存在自动停止（日常更新推荐）
cargo run -- replies -e 27066519444214 --incremental

# 增量爬取，最多翻10页
cargo run -- replies -e 27066519444214 --incremental -p 10

# JSON 格式输出
cargo run -- replies -e 27066519444214 -f json
```

**参数说明**:
- `-e, --euid`: 用户加密 UID（从个人主页 URL 获取）（必填）
- `-p, --max-pages`: 最大获取页数（默认 0 = 自动）
- `-s, --page-size`: 每页条数（默认 10）
- `--incremental`: 增量模式（默认关闭）：从第 1 页开始爬，遇到整页 pid 都已存在即停止——
  基于虎扑列表时间倒序的特性，新数据只可能出现在最前面的页，因此不会重爬历史数据
- `-f, --format`: 输出格式（table / json / simple）

**euid 获取方式**: 打开用户个人主页 `https://my.hupu.com/{euid}`，URL 路径中的数字即为 euid。

### 获取发帖

抓取用户的发帖（主题帖）记录并存入 SQLite 数据库。

```bash
# 获取用户发帖
cargo run -- posts -e 27066519444214

# 获取更多页
cargo run -- posts -e 27066519444214 -p 5

# 增量爬取：只爬取尚未入库的新发帖，遇到整页已存在自动停止
cargo run -- posts -e 27066519444214 --incremental

# JSON 格式输出
cargo run -- posts -e 27066519444214 -f json
```

**参数说明**:
- `-e, --euid`: 用户加密 UID（必填）
- `-p, --max-pages`: 最大获取页数（默认 0 = 自动）
- `--incremental`: 增量模式（默认关闭）：只爬取尚未入库的新发帖
- `-f, --format`: 输出格式（table / json / simple）

发帖数据从用户个人主页 HTML 中提取，包含标题、摘要、板块、回复数、浏览量、点亮数、图片/视频标记等。

### 相似度分析

分析用户回帖中的重复/近似内容，使用 Jaccard 相似度算法进行聚类。

```bash
# 分析回帖相似度（默认阈值 0.5）
cargo run -- analyze -e 27066519444214

# 使用更高阈值（更严格，只匹配高度相似的内容）
cargo run -- analyze -e 27066519444214 -t 0.8

# JSON 格式输出
cargo run -- analyze -e 27066519444214 -f json
```

**参数说明**:
- `-e, --euid`: 用户加密 UID（必填）
- `-t, --threshold`: Jaccard 相似度阈值，0~1（默认 0.5）
  - 值越大越严格，只匹配高度相似的内容
  - 值越小越宽松，会匹配更多近似内容
- `-f, --format`: 输出格式（table / json / simple）

**算法说明**:
1. 对每条回帖进行中文分词（overlapping bigram）和英文 token 化
2. 计算两两之间的 Jaccard 相似度
3. 使用 Union-Find 算法聚类
4. 对非精确匹配组进行 centroid 验证，防止传递链误聚合
5. 输出每个相似组的代表内容、出现次数、板块分布

**参数说明**:

启动后打开浏览器访问 `http://localhost:3000`，功能包括：

#### 回帖分析
- **统计概览**: 总回帖数、独立回帖、重复/相似回帖、重复率
- **板块分布**: 各板块回帖数的环形图
- **月度趋势**: 月度发帖量的折线图
- **词云**: 高频词可视化（基于 jieba 分词）
- **深度分析**:
  - 时段活跃度（24小时分布）
  - 周活跃分布
  - 回帖长度分布
  - 点亮统计（总点亮、平均点亮、最高点亮）
  - 回帖最多的帖子排行
- **相似回帖组**: 展示聚类结果，可展开查看每条详情
- **AI 智能分析**: 基于 AI 的用户画像（关注领域、立场倾向、核心观点、行为模式）

> **增量 AI 分析**：AI 画像默认采用增量模式——首次分析为全量，之后点击「增量更新」
> 只分析新入库且尚未分析过的回帖/发帖（通常 1~2 次调用），再与旧画像合并，token 消耗可省 90%+；
> 已分析过的内容（即使重复抓取刷新了数据）不会重复分析；「重新分析」按钮强制全量重算。
> 存量缓存自动回填已分析标记，无需重新分析；上次分析有失败批次的用户保留全量重试。

#### 发帖数据
- **统计概览**: 总发帖数、总回复、总浏览、总点亮、视频帖数
- **发帖板块分布**: 环形图
- **发帖列表**: 展示标题、板块、视频/图片标记、互动数据
- **AI 智能分析**: 基于 AI 的发帖画像（内容风格、话题焦点、互动分析）


#### 通用功能
- **相似度阈值调节**: 实时切换相似度阈值查看不同粒度的聚类结果

#### 查成分（独立 Tab）
- 输入用户 euid，生成虎扑"成分卡"（主混迹板块、粉籍判断、抽象/水贴指数、点亮质量、口头禅、经典语录、历史黑点、核心特长、热评总结），以卡片样式展示
- 结果缓存可反复查看（显示"已缓存"标记），点「重新生成」强制刷新

#### 懂哥履历（独立 Tab）

围绕一个话题，把用户已收录的发帖与回帖写成轻松、有细节的「话题小传」：看看他夸什么、吐槽什么、各时期怎么评价，还有哪些原声值得读。

1. 在顶部输入或选择用户 euid，切换到「懂哥履历」。没有历史记录时先抓取数据。
2. 输入话题，可填写逗号分隔的别名（如 `SU7，小米SU7`），选择日期范围；留空表示全部已收录时间，日期按北京时间计算。
3. 点击「查看数据 / 已有报告」，检查命中条数、独立帖子数、月份覆盖和缓存报告。这一步不调用 AI。
4. 点击「AI 生成履历」，使用现有 AI 配置生成有趣的概括、观点看点、原声精选和各期评价。
5. 点击「原文与上下文」查看高亮引文、他人引用上文和采集时间，或打开原帖定位回复。

报告按「一句话懂他 → 鲜明看点 → 原声精选 → 那阵子在聊什么」组织。每期解读当时对具体事物的评价与表达方式，不刻意寻找改口或强行编出态度转变；新版不再生成或展示前后对照。文风允许贴切比喻与善意调侃，但原话、数据和背景必须有依据。

原声精选兼顾有意思的发言和实际点亮较多的评论。点亮数直接取采集时的回帖 `light_count` 或发帖 `lights`，不由 AI 编写，也不当作观点正确的证据。零点亮或旧缓存没有点亮数据时只标为代表发言。每条精选有简短点评，可展开原文与他人上文。

最多取 60 条分析样本：数据较多时，保留最多 20 条高点亮记录，同时用其余名额覆盖不同时间，并填补重叠名额。同月相同正文与语境的重复记录取实际点亮最高的一条作为代表，不累加点亮数。长正文最多取前 1,200 字、引用上文最多 400 字送给 AI；完整已存文本仍可查看。发帖数据只有标题和摘要。话题及手工别名使用字面匹配。

报告缓存于 SQLite 的 `opinion_history` 表中。旧版报告仍可读取，并提示点击「重新生成履历」使用新风格；数据和报告模板版本共同参与过期检查，不会把旧格式当作最新结果。程序校验来源与引文，观点看点和精选只能关联已校验的发言。数据范围与采样限制收在可展开的阅读说明中。

引文由程序直接从原始正文提取：AI 选择来源记录及片段编号，程序回填相应连续原文，不使用 AI 重写的引文。若片段编号缺失或无效，展示该记录参与分析的完整正文并注明未定位具体片段；不存在的来源和空正文仍会被拒绝。原文是否支持 AI 的观点解读，仍需结合上下文判断。

接口：`POST /api/history`，JSON 参数为 `euid`、`topic`、可选 `aliases`、`start`、`end`、`generate`、`refresh`、`api_key`、`provider`。默认只预览；`generate: true` 才可能调用 AI，已有有效缓存且未指定 `refresh` 时复用缓存。

履历生成对 DeepSeek 显式使用非思考模式，确保输出额度用于 JSON 正文。如果服务返回空正文，自动改用普通 JSON 提示重试一次（单次生成最多两次 AI 请求）；输出截断、认证失败、余额不足、限流与引用校验失败分别提示，不会无限重试，也不会把模型的思考内容作为报告。

每次履历生成使用新连接池，建连超时为 15 秒、单次请求总超时为 120 秒。仅建连失败（请求尚未送达）允许换新连接重试一次，与空正文重试共用最多两次请求的上限；发送或接收过程失败不会自动重发。网络错误按 DNS、安全连接、建连、发送和接收阶段提示，日志不记录密钥和原始错误正文。

开发验证：`cargo test --offline`；前端请求生命周期测试：`node --test tests/history-tab.test.mjs`（Node 22+）。

#### AI 问答 Tab 内的魂穿子 Tab
- 在 AI 问答页顶部切换「💬 问答 / 👻 魂穿」，复用问答的聊天气泡界面
- **魂穿**: AI 学习目标用户最近回帖的说话风格
  - **嘴替**：描述场景或粘贴对方发言，AI 以该用户口吻生成一条虎扑回帖
  - **对线模拟**：多轮对话，AI 全程扮演该用户，可延续话题追问
- 切换用户自动清空，对话和卡片不会串人

### 查成分 / 魂穿（CLI）

```bash
# 生成用户成分卡（JSON）
cargo run -- profile -e 27066519444214

# 成分卡文本格式
cargo run -- profile -e 27066519444214 -f text

# 魂穿：以该用户口吻生成一条回复
cargo run -- ghost -e 27066519444214 -c "勇士今年能不能夺冠？"

# 魂穿对线模式
cargo run -- ghost -e 27066519444214 -m chat -c "你为啥天天黑库里？"
```

**参数说明**:
- `profile -e, --euid`: 用户加密 UID（必填）；`-f, --format`: json / text
- `ghost -e, --euid`: 风格来源用户（必填）；`-c, --content`: 对方发言/话题（必填）
- `ghost -m, --mode`: reply（嘴替，默认）/ chat（对线）；`-f, --format`: text / json

> 两者都需先通过 `replies` 命令抓取目标用户的回帖数据，且配置了 AI `api_key`。

#### AI 问答
- **自然语言提问**: 基于用户的历史发帖回帖数据，用自然语言向 AI 提问
- **多轮智能检索**: Agent 自动决定检索关键词和搜索范围，最多进行 5 轮检索后给出最终回答
- **实时过程展示**: 每轮检索的关键词、推理过程、搜索结果数量实时流式推送到前端
- **多轮对话**: 支持追问，携带对话历史上下文
- **建议问题**: 提供预设问题快速体验
- **请求溯源**: 可展开查看每次问答的完整 Agent 决策过程和用户上下文

#### 互动图谱（独立 Tab）
- 基于已抓取回帖的**引用关系**（quote 字段）构建社交关系图，无需额外抓取
- **行星轨道布局**: 本人（紫色）固定在中心，互动对象按互动次数分环环绕——**离中心越近 = 互动越多**
- **防重叠排布**: 星球尺寸随数量全局自适应（星球越多单个越小），分环按"实际半径 + 同环弦长"计算并留出环间隙，同环**整环刚性公转**（不再相对漂移互相压盖）——任意两颗星球在几何上保证不重叠
- **降噪**: 标签智能避让（只画重点、互不压盖，可切换「避让/全部/隐藏」），悬停时其余星球与标签淡出聚焦；工具栏可调星球数量（20/30/40/60）与暂停公转，方便看清拥挤区域
- **圆圈大小** = 互动次数为主 + 点亮为辅；**颜色 = 平均点亮质量**: 灰(<1) → 青(1~4) → 蓝(4~10) → 橙(10~25) → 红(≥25)，高亮节点带光晕
- **悬停节点/连线**: 显示该对象的互动次数、总点亮和最热的 3 条引用（按点亮数）
- **点击节点/连线**: 右侧抽屉展示全部互动回帖，含原文、引用内容、点亮数、时间，支持分页加载和跳转原帖
- 支持滚轮缩放、拖拽平移、双击重置视图，深浅色模式自适应；系统统称（如"小黑屋住户"）自动过滤

> 数据来源为 `replies` 表中 `quote_username` 字段，需先通过 `replies` 命令抓取用户回帖。

## 注意事项

1. Cookie 可能会过期，如果遇到登录失败提示，需要重新获取后更新 `config.json`
2. `smidV2` 与你的设备绑定，通常不会经常变化
3. 板块 ID 可以从抓包的 `topicId` 字段获取
4. 帖子 ID 即帖子 URL 中的数字部分
5. AI 分析功能需要配置 `api_key`（在 `config.json` 中设置 `provider` 和 `api_key`），每次分析会消耗 API 额度
6. 首次使用 `replies` / `posts` 命令会创建 `hupu.db` 数据库文件
7. 回帖数据是 Web 分析的基础，需要先通过 `replies` 命令抓取数据，再启动 Web 服务查看
